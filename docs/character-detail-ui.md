## 研究力Lv1から短縮を適用（2026-11-25・最新仕様）

ユーザー指定の計算仕様に変更し、研究力・研究力＋Lvを再生産表示に接続した。体力・攻撃力は引き続きお宝補正前のLv1基礎値として扱う。DBの格納値は変更しない。

- 中国の伝統: `floor(発動率 × 3 / 10)` F。
- 研究力: `(Lv + プラスLv) × 6` F。Lv1＋0で6F、Lv20＋10で180F。
- 再生産: `max(60, DB再生産F - お宝短縮F - 研究力短縮F - コンボ追加短縮F)`。
- 最大設定・コンボなしは270F短縮。かさじぞう396F→126F（4.20秒）。
- 研究力の入力範囲はLv1〜20／＋Lv0〜10のまま。

コンボ追加分には今回の6Fを含めない。従来の計算で `B = お宝率×0.3 + (Lv合計−1)×6` としたときの `floor(B×(1+コンボ率/100)) - floor(B)` を維持する。最大時の追加は26／52／79F、合計短縮は296／322／349Fとなる。お宝率に端数Fが発生する場合も、従来関数のコンボあり／なしの差分を維持する。コンボの実画面設定・集計は未実装であり、これは既存計算関数の引数とテストでの対応。

**未確定の点:** anypupilの表示が現在のbattlecatsinfoのcdより+10F、現行DBがHTMLより+6Fとなる理由。異なるデータ版や独自変換の可能性はあるが、変換コードがないため固定補正の存在・意味は断定しない。したがって「DB値から一律6Fを引く」処理は採用しない。かさじぞう396Fから指定の264Fを引くと132Fとなり、ユーザー提示の126Fとの整合性は未確認のまま。

### 独立計算関数と未接続の理由

`treasureModifiers.ts` に、**補正前と確認済みの入力専用**の関数と単体テストを追加した。DB保存値の条件が未確定のため、`statValues` にはまだ接続していない。UIにも「元データの補正条件を確認中」と表示しており、設定変更によるステータス再計算は未完了。

- 体力／攻撃力: `floor(レベル補正済み値 × (200 + お宝率) / 200 × (100 + 本能合計率) / 100 × (100 + コンボ率) / 100)`。
- 適用順はレベル→お宝→本能・超本能→コンボ。既存の中間値を丸めない方針を保ち、最終整数化だけ切り捨てる。倍率を十進有理数としてBigIntで計算し、浮動小数点誤差による1の欠落を防ぐ。
- 再生産短縮: `floor((お宝率 × 0.3 + (研究Lv + 研究＋Lv - 1) × 6) × (1 + コンボ率 / 100))`。
- 再生産結果: `max(60, 補正前F - 直接短縮本能F - 上記短縮量)`。直接短縮本能Fは独立関数の引数のみで、既存本能パーサーには未接続。ゲーム仕様としてこの順序が確認済みという意味ではない。
- 既存のDPS・攻撃間隔本能・コスト計算・フレーム表示は変更していない。攻撃間隔本能を取得する際の既存の四捨五入も今回の変更対象外。

## 表示ルール

- 形態ボタンは `forms` の順序・件数どおりです。初期表示は末尾の形態で、番号やIDを決め打ちしません。
- キャラクター名・レアリティ・略称・限定区分・コラボはJSONから取得します。任意項目がnullなら表示を省略します。
- 形態名・説明・初登場バージョン・ステータス・対象・効果・能力・本能を選択形態に連動させます。第3形態のバージョンは過去の依頼文ではなく今回のJSONの `13.4.0` を表示します。
- 体力・攻撃力はLv1基準。初期選択レベルは1です。レベルを変更しても基準値は変えず、その旨を表示します。
- 時間は30F=1秒で換算します。DPSは未対応、独立した攻撃範囲フィールドはないため「未提供」とします。「範囲攻撃」「全方位攻撃」はJSONどおり能力に表示します。
- 本能の3分類と本能区分（本能/超本能等）を表示できます。提供JSONには能力本能だけが存在し、超本能の実データはありません。
- `effect_targets` / `effects` の本能配列は原本で空のため、非空データのID・名称プロパティは能力本能と対称の暫定型です。正式な非空レスポンスが届いた際に契約を照合してください。テスト内だけで3分類を検証し、原本へ架空データは追加していません。
- 使用NPは `np_costs` の選択レベルまでの和、次NPは次の要素です。最大レベル・費用がnull/欠損なら「未提供」とし、架空の費用を補いません。
- `parameter_values` のaction/base/step等は保持するだけで、ステータス補正や能力追加を計算しません。
- 配列が空なら「登録なし」、nullなら「未提供」と表示します。本能がない形態にも空状態のカードを表示します。

## 基本ステータスと本能補正（2026-10-30）

Lv1〜60の基本値を `model/baseStats.ts` で計算後、`model/talentModifiers.ts` が `attack_buff_percent` / `defense_buff_percent` のbase＋step×本能レベルを解析・適用します。Lv0はbase値に関係なく未適用。ID・名称・NPでは分岐しません。同じステータスの補正率は加算して一度乗算する暫定仕様で、中間値は丸めず、表示形式は既存処理を維持しています。実ゲームの成長・端数処理との一致は未検証です。

DPSは補正後の攻撃力から `model/dps.ts` で再計算し、小数点以下を暫定的に切り捨てます。第3形態は連続攻撃の内訳がないため引き続き未対応です。未対応パラメータ・不正な係数は適用せず、解析結果の `unsupportedParameters` / `invalidParameters` にキーを保持します。actionだけでは補正しません。本能玉・お宝・コンボ・耐性等の戦闘処理は対象外です。

今回の確認は型チェックのみ。新規テスト・モックは追加せず、既存E2Eの体力本能適用後の期待値1箇所だけ更新しました。

## 本能の形態別適用

`model/talentApplication.ts` の `canApplyTalents` / `applicableTalents` を適用側の共通入口とする。APIの `form_number` が仕様の `form_no` に相当し、整数かつ3以上の場合のみ通常本能・超本能を適用する。キャラクターID・能力コードによる例外は設けない。

`statValues` は共通入口を通した本能だけを計算に渡す。第1・第2形態では本能による体力・攻撃力・コスト・攻撃頻度の補正が無効になる。お宝・研究力・レベル補正の入力や計算式は変更しない。既存の本能レベル上限・Lv0未解放の扱いも維持する。

設定は従来の `CharacterSettings.talents` にキャラクターIDと本能IDのキーで保持する。形態切り替えはこの設定を書き換えない。本能欄の設定レベル・使用NPは保持し、第1・第2形態では補正表示を「この形態では適用されません」とする。

能力・効果・対象属性の表示は現在、選択形態が元から持つデータのみを使用している。本能による能力追加・パラメータ強化・属性追加、再生産の本能補正は未実装であり、今回新たな計算式を追加していない。今後これらの適用処理を実装するときも `applicableTalents` を通した本能情報を使用する。未実装の能力が第3・第4形態で反映できるようになったことを意味しない。

移動速度上昇は `move_speed_increase` の `base + step × 本能Lv` を基礎移動速度へ加算する。割合計算や丸めは行わず、Lv0は未適用。共通の形態判定で第3形態以降だけに適用し、設定値は形態切り替えで保持する。
